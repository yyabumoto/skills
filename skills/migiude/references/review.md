# レビュー（自分の PR の指摘対応）

## 自分の PR: push から マージまで

1. **push 前のセルフレビュー**: 差分全体を読み直す。プロジェクトにレビュー用の仕組み（ローカルのレビュー環境、レビュー用スキル）があれば使う。ユーザーがそこでコメントを付けたら、全件読んで対応する。
   - レビュー用スキルやレビューエージェントの指摘は、[orchestrate.md](orchestrate.md) の「指摘の重さと対応」に従い、medium 以上だけを直す。直し方が分かれたら、推奨する案で進める。
   - 指摘のうち今回の目的に含まれない別件は直さず、SKILL.md の「本筋以外の発見」に従って起票する。
   - ユーザーや人のレビュアーが付けたコメントは、重さで省かずに全件扱う。
2. **push・PR 作成**: セルフレビューを終えたら作業ブランチを push し、そのブランチに対応する PR がなければ作成する。PR テンプレートがあれば従う。本文は [writing.md](writing.md) の「PR 本文」に従う。インフラ変更など影響の大きいものは draft で作成する。
3. **CI の確認**: 結果を確認し、落ちていれば原因をログから特定して直す。推測で再実行しない。
4. **指摘への対応**:
   - コメントを 1 件ずつ読み、妥当性を判断する。妥当でないと考えるなら、根拠を添えてユーザーに相談する（勝手に却下しない）。
   - 妥当だが今回の範囲外と考える指摘は、今回直すか、起票して別対応にするかを、根拠を添えてユーザーに相談する。人のレビュアーは今回の PR で直すことを求めている場合がある。
   - 妥当な指摘で直し方が分かれたら、ユーザーに聞かずに推奨する案で直し、選んだ案と理由を対応表に書く。
   - 修正したら、どのコメントにどのコミットで対応したかの対応表を作る。
   - 返信は**元のスレッドに**返す。新規コメントとして書かない。
   - 返信の投稿、スレッドの resolve は、ユーザーの指示がある場合だけ行う。指示がなければ返信文案と対応表を渡す。
5. **PR 本文の更新**: ユーザーから更新の指示があり、変更内容が本文とずれていれば更新する。更新前に現在の本文を読み、ユーザーが手で直した箇所を残す。
6. **マージ後**: ブランチ・worktree を畳み、ローカルのデフォルトブランチを最新化する。

## 監督モードのレビューエージェント

- 指摘の重さは、[orchestrate.md](orchestrate.md) の「指摘の重さと対応」の high / medium / low で付ける。今回の目的に含まれない指摘は「別件」として分けて書く。
- 「要件を満たさない」とする指摘は、[orchestrate.md](orchestrate.md) の「要件を変える判断の基準」に従い、該当する要件、対象ケースへの適用理由、満たせていない振る舞いを示す。合意済みの要件を満たす別案は、設計上の指摘として重さを付ける。

## よくある失敗

- lint やテストが落ちたまま「対応しました」と言う → push 前に自己検証を必ず実行する。
- 返信を新規コメントで書く → スレッドの返信 API を使う。
- 指摘されていない箇所まで直す → 指摘の範囲だけ直し、気づいた別件は SKILL.md の「本筋以外の発見」に従って起票する。
